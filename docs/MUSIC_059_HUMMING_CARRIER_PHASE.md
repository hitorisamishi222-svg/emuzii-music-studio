# MUSIC-059 — 長尺ハミングの5倍音キャリアを元音符位相で再開

## 背景
MUSIC-058でハミングのビブラートLFO位相と振幅は分割WAVへ引き継げたが、音高そのものを鳴らす5本のサイン波は新しいOfflineAudioContextで必ず位相ゼロから再始動していた。このため100msクロスフェードで緩和しても、分割地点で波形が干渉して音量や音質が変化する可能性があった。

## 修正（開発ブランチのみ）
- `app-v10.3.2.html` の `scheduleTone()` の共有 `addOsc` で、`guideInstrument === "humming"` かつ `type === "sine"` のときのみ、実音符開始からの経過時間で音響キャリアの位相を補正する。
- 部分レンダリングの開始位置を `overlapStart-gStart` で取り、実際の倍音オシレーター周波数 `osc.frequency.value` を乗じた小数周期を `PeriodicWave` の係数で復元する。
- 基本音＋4倍音の計5本すべてを対象とし、MUSIC-058のビブラートLFO用位相処理は維持する。
- `createPeriodicWave` または `osc.setPeriodicWave` が非対応の環境では従来の合成に安全に戻る。
- 元音符の先頭では元の標準サイン波を使う。他楽器、楽譜、録音原音、ガイド保存データ、MIDI、SONG ID、通常の100msクロスフェードや本番環境は変更しない。

## テスト
- `tests/master-multitrack-contract.test.mjs`：5秒と10秒の分割区間に対して5本全ての各倍音が元音符基準の位相になることを数式比較する。元音符の音高と時刻の不変、ピアノ非影響、周期波APIのない環境の安全性を回帰確認する。
- `tests/master-multitrack-browser.test.mjs`：13秒の合成プロジェクトにある7秒の持続ハミングから44.1kHz WAVを出力し、5秒・10秒の両境界で2本のビブラートLFOと5本のキャリアが再位相設定されていることをWeb Audioブラウザ経由で検査。音量、休符、終盤音、外部API未使用も維持。

## 制限
本タスクは合成波形の位相の連続性と出力条件の検証であり、人間の歌声へ変換したことや、ユーザーのフル尺実歌唱で聴感合格したことを意味しない。100msクロスフェードは従来通り維持し、フィルタ内部状態まで全チャンクで完全一致すると断言しない。GPU使用・実機テスト・本番公開は実施しない。既存のMUSIC-040/050/060/070は保留のまま。
