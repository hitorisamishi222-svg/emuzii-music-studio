# MUSIC-056 — 長音ハミングの共鳴変化と分割WAV境界の整合

## 狙い
MUSIC-055で伸ばす音に遅れてビブラートを加えた後も、固定960Hzの声風共鳴だけでは全曲の音色が単調に感じられる可能性があった。実歌唱の再現や人声変換と混同せず、ハミング音色の微小な時間変化を追加する。

## 実装（開発ブランチ限定）
- `app-v10.3.2.html` の `scheduleTone` にあるガイド音色 `humming` だけが対象。
- 音符長が0.65秒以上のとき、960Hzを基準として音符開始位置とMIDI音高から決定論的に±60Hzの音色差を作る。
- 音符全体の進行度に合わせ、フィルターの共鳴中心をさらに始めから終わりへ計80Hzだけ緩やかに移動。設定値は約860〜1060Hzの範囲。
- 音符を部分的に描画する場合も `overlapStart`、`overlapEnd` を元音符の位置で正規化して計算し、5秒/10秒のチャンク境界を跨いでも同じ絶対位置の共鳴値を一致させる。
- 短音（0.65秒未満）・ピアノなど他のガイド音色は変更しない。
- 元音声、音符、MIDI、保存DB、SONG ID、TAKE、音量バランス、既存100ms WAVクロスフェードを変更しない。

## テスト
`tests/master-multitrack-contract.test.mjs` に追加:
1. 195秒に跨がる1.2秒の模擬音符を分割して呼び出し、境界の共鳴周波数の一致、数値範囲、非破壊性を検査。
2. 短音とピアノでは新しい共鳴オートメーションを一切追加せず従来の値を維持。
3. 既存のStudio⇄Vocal往復、ガイド／MASTER、保存・復元など影響範囲の回帰試験を走らせる。

## 限界
上記はパラメータの連続性と既存機能の検証であり、195秒の実際の歌唱を再生・聴感評価したものではない。長い人間の歌声に対する自然さ、端末の発熱/メモリ、実機、外部GPU、本番公開はいずれも未実証。音声合成モデルではなくWeb Audioの音色制御のみ。
本番 `main`、本番URL、既存の4つのブロッカー（MUSIC-040/050/060/070）には一切変更しない。
