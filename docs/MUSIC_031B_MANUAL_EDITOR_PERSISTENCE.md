# MUSIC-031B — 端末内プロジェクトに手動メロディ・コード・曲構成を保存

2026-11-03 開発ブランチ。元音声・本番DBは変更しない。

## 発見
従来の「音源を含めて端末に保存」はトラックと作曲フォームの一部を記録する一方、`state.guideNotes`、`state.chordProgression`、`state.songForm`を含まない。これらは別の「編集設定JSON」には含まれるが、通常の端末内作品保存では戻らない。

## 修正
- 保存開始時の編集状態スナップショットに`manualEditor:{guideNotes,chordProgression,songForm}`を追加。元の保存トラック、録音Blob、SONG ID/TAKEを維持する。
- 復元する前にガイド音符の時刻/音程/長さ、コードルート・接尾記号、曲構成の時刻・密度・各配列のサイズを検査。異常があれば現行作品の状態を維持したまま拒否する。
- 古いプロジェクトに`manualEditor`がない場合は既存の音源復元を妨げず、3種類の編集内容は空とする。他の作品の古い編集内容を混入させない。
- 復元後はピアノロール・コード入力・曲構成表示を同期する。
- 単体テストで保存途中の編集による値の混在と不正メタデータを検査。合成プロジェクトをChromium上で開き、保存→リロード→ガイド音符/コード/曲構成一致を検証。

これは上記3種類の編集データの永続化。診断履歴・複雑なアレンジ編集の全状態まで保証するものではない。Android R6実機テストと実GPUは引き続き保留。
