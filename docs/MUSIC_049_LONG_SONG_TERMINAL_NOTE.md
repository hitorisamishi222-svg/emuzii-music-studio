# MUSIC-049 — フル楽曲の最後100msを落とさないガイド解析

## 発見
従来の `extractGuide()` は、音声を12kHzへ落として1024サンプル（約85.33ms）の窓で解析する際に、`i+win < data.length` の条件で窓の先頭を走査していた。音声の最後でフル窓が取れない時間帯は実質的に音高解析から除外され、短い語尾・曲末尾音符が欠ける可能性があった。

## 修正内容
- `guidePitchWindow(data,start,size,scratch)` を新設。音声内部では通常のFloat32Array viewを使用し、最後の部分窓だけ再利用する1024サンプルの作業領域に音声データを複写して不足分を0で埋める。
- 解析ループを`i < data.length`まで進め、進捗用総フレーム数を`Math.ceil(data.length/hop)`として最終フレームまで走査する。
- 最後に生成されたガイド音符の終点を`Math.min(duration,r.end)`で制限し、元の曲の長さを超える音符を保存しない。
- 元録音・トラック・手編集の音符・MIDI・SONG IDは変更しない。新しいプロジェクトも本番URLの変更もなく、`feature/vocal-recorder-v1`のみ更新。

## 検証結果
- 単体テスト：1024サンプルの完全窓と曲末尾の部分窓に関して、残余の0埋め、前フレーム内容の残留防止、元の音声配列を一切変更しないこと、最終フレームまでの走査条件を検証。
- 実Chromium：195.22秒・16kHzの音声をテストでローカル生成し、C4（0.3秒付近）、A4（64.2秒付近）、E4（129.5秒付近）、C5（195.12〜195.22秒）を埋め込み、一般ユーザーと同じファイル読み込み・「ガイドにする」操作で解析。
- UIのピアノロールに表示された結果：
  - C4：0.25秒開始、0.74秒長
  - A4：64.15秒開始、0.87秒長
  - E4：129.45秒開始、0.83秒長
  - C5：195.10秒開始、0.12秒長（曲の終了195.22秒以内）
- **4音すべて検出、余計な音符なし**。最後の100msのC5は欠落しなかった。
- 既存の歌入れ・ガイド音程・息/子音入り歌声・WAV分割・MASTER・保存/復元の実ブラウザ回帰テストも合格。
- CI: https://github.com/hitorisamishi222-svg/emuzii-music-studio/actions/runs/41943492789

## 境界条件
このテストは3分超の「合成した疎な歌声」の耐久・末尾検査。人間のフル歌唱や伴奏付き多重録音の認識精度と聴感評価を保証しない。歌い出し時刻についても、この試験でのC4/E4などに最大数十msのずれが残る。iPhone/Android実機録音・保存復元・音ズレ確認、共通エンジンの実API、GPU生成、本番公開の4ブロッカーは未実施のまま維持する。
