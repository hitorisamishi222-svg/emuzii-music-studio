# MUSIC-057 — 長音ハミングの分割WAV音量エンベロープ連続性

## 問題と影響範囲
既存の `scheduleTone()` は長い音符を 5秒/10秒 WAV チャンクで分割するたびに、オシレーターの聞こえる区間の頭をアタック開始・末尾をリリース終了として計算していた。MUSIC-045 の100msクロスフェードだけでは、元の音符が継続中でも擬似的な減衰・再アタックが重なるため、WAV境界付近でハミングの音量が落ち込む可能性があった。

## 開発ブランチの修正
- `app-v10.3.2.html` の `scheduleTone()` 内、`guideInstrument === "humming"` かつ元の音符長 `note.duration >= 0.65` 秒の場合のみ、元音符の開始・終了に固定した ADSR を描画する。
- 元音符のアタック・ディケイ・サステイン・リリースを固定し、分割区間の先頭では正しい途中の音量から開始。境界での不要なリリースや再アタックを行わない。
- 最後の元音符のリリースは保持。途中から再生・書き出しても元音符のリリース進行度に合わせた値で開始する。
- 他のガイド音色、0.65秒未満の短音、原音、ガイド音符/MIDI、保存形式、既存100msクロスフェード、MASTERの明示ガイドONルールは変更しない。

## テスト
- `tests/master-multitrack-contract.test.mjs`：12秒未満の持続音が5秒・10秒の継ぎ目を超える場合、持続音量を維持するか、真の音符末尾だけでリリースするか、元データ不変かを検査。音符末尾だけを切り出すケースと、短いハミングやピアノの旧仕様も検査。
- `tests/master-multitrack-browser.test.mjs`：既存13秒のChromium/Safari互換WAVサンプルを7秒持続する模擬ハミングに更新。5秒・10秒の2境界でRMSを比較し、44.1kHz、全フレーム長、休符と末尾音の保持、外部APIなしを確認。
