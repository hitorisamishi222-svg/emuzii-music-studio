# ASAHI REALTIME PITCH CORRECTOR — 引継ぎ / MUSIC-101

作成日: 2026-11-12。優先対象: ColorSing。既存MUSIC-100と本番・元音源を保護し、Android外部入力・AG03MK2・iPhone接続を将来検証する。アプリ改造は行わない。

## 現状分析
既存の `integration/local-sample-sampler.js`、`integration/independent-arrangement-renderer.js` は**オフライン音符演奏・WAV合成**。これらを低遅延の歌声入力・ピッチ検出・時間伸縮としてそのまま流用できない。リアルタイム入出力、ピッチ推定、自然なピッチシフト、Android音声経路は新規に検証が必要。

## 方法の妥当性
1. まず基準音の存在を明示。測定Hzだけでは正しい音高と歌唱ミスを区別できない。曲のメロディーや手動指定音がない場合は**自動補正しない**。
2. 音程推定は有声音・信頼度の判定が必須。声質やビブラートを守るため、自然モードでは小さいズレを残し、明らかな逸脱だけ少量補正。フレーズ単位の安定性・ヒステリシスは後続。
3. 音量ピーク制御は別の独立モジュール。入力切断・処理失敗時は予期しない爆音を出さず、明示的なバイパス/ミュートの安全設計を別途実装。
4. Android側は低遅延のネイティブ音声I/O（AAudio/Oboe等）を候補として実機で検証。AG03MK2がUSBホストとして接続できるか、Android側のUSBオーディオ入出力経路、iPhone側の認識、原音二重取り込みを**未確認**とする。
5. レイテンシーは入力→出力の往復測定と、録音後の波形位置合わせを別管理。ワンフレーズ録音のタイミング補正でモニター遅延は解消しない。

## 最初の実装（設計段階）
`integration/realtime-pitch-correction-policy.js`: 参照音高・検出音高・信頼度・有声音フラグを受け、natural/standard/powerfulの**部分補正量だけ**を計算。自然モード既定。音声の加工は行わない。入力範囲を検証し、不確実な推定では補正0。音声ストリーム、Android APK、ColorSing接続は未実装。
