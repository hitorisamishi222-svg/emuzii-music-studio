# MUSIC-045 — 長尺のハミングガイドWAVの境界品質

## 背景
`buildChunk(start,end,sampleRate)` は新たな OfflineAudioContext で5秒・10秒の範囲を独立レンダリングしていた。ハミングのオシレーター・ビブラート・エンベロープは各区間の境界で再開始されるため、長い音符が境界を越える場合に波形の段差や音色の不連続が生じ得た。

## 開発版の修正
- `renderChunkedMixPcm(duration,rate,chunk,onProgress)` に一般WAV書き出しとiPhone互換用の共通分割合成経路を統合。
- 隣接するチャンクを100ms重複して合成し、出力時にリニア・クロスフェード。サンプル位置は整数フレームで計算する。
- 重なったフレームは一度だけ書き込み、WAVヘッダーとPCM長が厳密に一致する。
- 各 OfflineAudioContext の最大処理期間はチャンク本体＋100msに抑え、フル曲全体の OfflineAudioContext を新たに確保しない。
- 元のガイド/音声Blob/曲構成/MIDI/SONG ID/保存DBへ変更を加えない。`main` と本番公開URLは触らない。

## 検証結果
- 5秒 iPhone互換・10秒 desktop 分割でサンプル数と100msクロスフェード波形の単体テストが成功。
- 195.22秒の*模擬*チャンクテストで所定のフレーム数と最大レンダリング区間を検証。実際の195秒音源を音響検査したことは意味しない。
- 13秒の*実Chromium*テストで、5秒と10秒をまたぐ持続ハミング音、終盤音符、休符、正確な44.1kHz WAV長、外部生成API未使用を検証。
- 既存の歌入れ、MASTER書き出し、保存と復元、初期ガイドOFFの回帰テストも成功。
- CI: https://github.com/hitorisamishi222-svg/emuzii-music-studio/actions/runs/41904968011

## 評価と次の課題
本変更はWAVの分割境界を滑らかにする措置。実歌唱の音質・音程認識精度・音符変換精度、5分超の端末メモリ/発熱、iPhone/Android実機の再生品質を保証しない。MASTERレンダリングは別経路のままで、本変更により分割化されたとは主張しない。元音源の劣化は発生しないが、独立チャンクの再発音による音色の差が完全に解消したかは別途聴感チェックが必要。
