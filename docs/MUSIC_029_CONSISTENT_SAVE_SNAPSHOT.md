# MUSIC-029 — 編集途中でも保存スナップショットの整合性を保持する

2026-11-03。開発ブランチだけに適用する。

従来`makeProjectRecord`は音声BlobごとにIndexedDBの非同期書込を待ってから各トラックの音量・名前・音符等を読み取っていた。その間にユーザーが別のトラックを変更・削除すると、同じ保存記録に編集前/編集後の状態が混在し得た。

- 音声本体は不変のBlob参照だけを固定し、保存開始時のトラックID・名称・音量・位置・音符・歌入れメタデータ・曲設計の設定を**最初のawaitより前**にコピーする。
- メタデータと音声の対応を同じ固定配列順序で管理し、その後にBlobを非同期保存する。ユーザーが編集を続けた内容は次回の保存に反映される。
- 元の音声は複製・変換・消去しない。既存のIndexedDB構造、保存ID、SONG ID、TAKEは変更しない。
- 人工的に最初のBlob書込を停止した状態で、歌TAKE名・音符・作曲名・トラック配列を変更し、完成レコードが変更前の一貫した状態であることを単体試験する。
- ブラウザでトラック名/音量/開始位置を明示保存→再読込して一致することも確認する。ページ終了直前の自動保存を保証するものではない。

これにより**個別の保存操作**の整合性を改善する。ブラウザ強制終了や端末容量不足など、全障害の復旧まで保証するものではない。
