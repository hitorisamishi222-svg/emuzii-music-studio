# MUSIC-036 — 複製トラックの再保存で音声を何度も書き込まない

2026-11-03 / 開発ブランチのみ

複製操作ではトラックIDは新規発行されるが、オリジナルと同じ不変Blobを共有する。この状態で保存すると、従来の`persistedBlobRefs`はBlob当たり1つのIDだけを記憶していたため、次の自動保存ごとに原音と複製音源の双方を再度IndexedDBへ書き込み、端末容量/書込時間/保存失敗のリスクを増やす可能性があった。

修正：Blobごとに「同じストレージ世代で保存済みの複数asset ID」を記録。初回は各IDを確実に保存し、同じセッションでの二回目以降は再書込を省略する。保存削除時の`audioStorageGeneration`更新により、空になったDBへ再保存する時は再度全IDを保存する。現行DBから復元した各Blobの参照IDもキャッシュへ安全に登録する。

Node単体テストに加え、実Chromiumで1音源の複製→保存→二度目の保存→ページ更新→2トラック復元を検証。生成した合成音源のみを使用。これにより音源の実バイト列、再生・録音、SONG ID/TAKE、既存本番データは変更しない。
