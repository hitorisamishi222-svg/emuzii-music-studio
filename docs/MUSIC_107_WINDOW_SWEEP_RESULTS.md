# MUSIC-107 — 窓長別の音程精度比較

## 作業前確認
メモリ・MUSIC-105不合格・MUSIC-106長窓研究版・専用CIを照合。既存本番・原音・開発済み音楽制作機能を保護。処理窓を短縮すると精度が崩れる可能性を検証する。

## 実装と方法
`integration/pitch-research-window-sweep.js` と `tests/pitch-research-window-sweep.test.mjs` を開発ブランチに追加。110/220/440Hzの24kHz合成持続音で、補正量-35/+35/+60セント、窓250/350/500/750msを比較。中央4096サンプルの自己相関音程推定で誤差を測定。入力PCMは変更しない。

## 実測
| 窓長 | ±20セント以内 |
|---:|---:|
| 250ms | 7/9 |
| 350ms | 9/9 |
| 500ms | 9/9 |
| 750ms | 9/9 |

250msの110Hz・±35セントは不合格（約+35.1/-33.6セント誤差）。350msの110Hz・+60セントは誤差+19.8セントで閾値ぎりぎり。CI合格は**診断プログラムの合格**であり、ライブ音声補正の完成を意味しない。

CI: https://github.com/hitorisamishi222-svg/emuzii-music-studio/actions/runs/43678960285

## 次工程
1. 窓長350ms未満でのPSOLA等の位相整合方式を別実装し、誤差ゲートを厳格化。
2. 音程推定器の倍音・無声音・ビブラート・音の立ち上がりの耐性を評価。
3. 実録音A/Bと声質・遅延を確認した後、Android実機音声経路を検証。

現在の窓長比較は音声品質、エンドツーエンド遅延、Android/AG03MK2/iPhone/ColorSing対応を保証しない。実機導入は禁止。
