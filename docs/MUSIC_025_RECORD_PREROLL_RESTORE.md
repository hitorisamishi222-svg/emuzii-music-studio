# MUSIC-025 — 歌入れカウントインの復元時ズレ防止（2026-11-03）

## 検出した問題
Studio の Webマイク歌入れは、録音終了後にカウントイン（既定3秒）を `trimBuffer` で再生用AudioBufferから除いている。しかし保存プロジェクトにはカウントインを含む**元のBlob**だけが保持されていたため、復元時 `decodeBlob` がカウントイン付き音源を再生し直す。つまり保存前後で歌声タイミングが変化する不具合。

## 修正
- 新規のWeb歌入れトラックに `recordTrimStartSec` を追加。実際に除いた秒数を記録する。
- `makeProjectRecord` に数値を保存し、`restoreProjectRecord` は元Blobをデコードしてから同じ秒数だけ再びトリムする。元の録音Blobは一切加工・上書きしない。
- 負値、非有限値、録音尺を超えるトリムなど不正な保存メタデータは復元前に拒否し、編集中の作品を保持する。
- 旧保存レコードにこの項目がない場合は0秒として扱う。旧作品に補正量を**推測して適用しない**。

## 検証範囲
合成WAVを使用するブラウザ検査では、1.3秒の元音声を0.5秒トリムして保存→ページ更新→再読込→完成WAV出力し、音声が0.3秒付近で始まること、元Blobのバイト数が変わらないことを確認する。不正な100秒トリムは拒否し、現在のトラックを維持する。

これはWeb録音の保存復元処理の修正。Android実機録音テスト（MUSIC-050）とは別であり、既存の古い保存レコードに失われたトリム秒数を復元できるとは主張しない。
