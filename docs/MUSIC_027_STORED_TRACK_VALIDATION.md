# MUSIC-027 — 不正な保存済み編集情報から現行作品を守る

2026-11-03 / 開発ブランチのみ / 保存形式は継続

## 発見した問題
復元処理は音声Blobの存在と復号を検査する一方、保存済みトラックの種類・音量・PAN・開始位置・フェード・音符の値を描画前に検査していなかった。例えばPANが文字列やnullなどの場合、`renderTracks` の `toFixed` などが例外を投げる可能性があり、旧コードでは`state.tracks`入替後のため編集中の内容を失い得た。トラック種別はHTMLへ直接挿入される経路もあった。

## 修正
- 保存トラックを順番に正規化してから音声を照合。旧バージョンで省略された音量・PAN・開始位置・フェードは安全な初期値を使う。
- 不正な数値、トラック種別、壊れた音符、重複ID、過剰なトラック数・音符数、異常なBlob参照は**編集中状態に触れる前に拒否**する。
- 原音Blob、SONG ID、TAKE、現行DBスキーマに変更はない。既存の古い形式からの移行は残す。
- 実Chromiumで、正規レコードを読み込んだ後にPANだけを破損させて再読込し、現在のトラックIDと画面を維持することを検査。v44の旧レコードでも省略数値のデフォルト復元を確認する。
- これは破損レコードの**安全な拒否**と旧数値省略の補完。全ての旧形式の内容を自動修復したとは主張しない。

Android実機テストは引き続き保留。正式本番・作品データへの直接変更はしない。
