# MUSIC-038 — 作品バックアップの書き出しと読み込みの整合性

開発ブランチの`ASAHIMusicBackup`は、音声Blobの読み込み上限を2GiB/件としていた一方、書き出し時にその上限がなく、非常に大きな音声ファイルでは**書き出せるが後で読み込めない**形式を作る可能性があった。書き出し前に同じ上限を検査する。また、トラックIDの重複も、書き出し時に明示拒否する。

これらはユーザー作品を変更しない事前検査であり、修復やファイル削除を勝手に実行しない。合成テストでは実際に大容量データを生成せず、サイズだけ大きく報告するテストBlobを使う。CRC32は誤転送・偶発的破損の検出用であり、暗号学的な改ざん証明や暗号化は提供しない。

合格条件：現行の音声付き・音声なしバックアップ往復、破損拒否、音声上限、重複IDのテスト。外部APIやGPUは使わず、実機は保留。
