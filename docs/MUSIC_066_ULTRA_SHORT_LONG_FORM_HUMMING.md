# MUSIC-066 — 20〜80ms短音の分割WAV保護と33秒の音量安定検査

## 目的
MUSIC-065までは80ms以上の合成ハミングを元音符に基づく振幅エンベロープで分割WAVへ引き継いでいた。20〜80msの極短い発音が5秒・10秒などのチャンク境界に重なる場合は、以前のクリップ相対ADSRによって不自然な再アタックや減衰が生じ得た。また、単一フレーズの検査だけでは曲の序盤・中盤・終盤で安定しているか見えにくかった。

## 実装
- `app-v10.3.2.html` のハミング専用振幅エンベロープ条件を `noteDuration >= .02` に拡張する。
- 20〜80msの短い音符についても、各音符の元の絶対開始時刻からアタック・ディケイ・サステイン・リリースを求める。分割位置が曲線の途中に入っても、前チャンク末端と次チャンク先頭で同じ振幅となる。
- 20ms未満の超短トランジェント、ピアノ・エレクトーンなどハミング以外は従来どおり。極短音で余計なビブラートを付けない。
- 従来のMUSIC-058/059（位相）、MUSIC-061（ブレス）、MUSIC-062（短い音程スライド）、MUSIC-063（フレーズ抑揚）、MUSIC-064/065（分割WAVと短音）の動作を維持。
- MIDIノート、元の声、原音声Blob、既存保存形式、既存本番URL、mainを変更しない。

## 検証
1. `tests/master-multitrack-contract.test.mjs`：20ms、35ms、45ms、55ms、75msのハミングで、分割点がアタック/ディケイ/サステイン/リリースにある場合の左右振幅を元の解析式と比較。音符非破壊、短音でのビブラート無しも確認。
2. 20ms未満の短音とピアノ・エレクトーンの以前の処理を維持することを回帰確認。
3. 180秒以降のタイムラインにある240音符の短音を模擬し、5つのキャリア倍音、数値の有限性、保存音符の不変性を確認。
4. `tests/master-multitrack-browser.test.mjs`：実Chromiumで33秒・44.1kHz・ステレオの互換WAVを出力。5秒・10秒・20秒の3地点をまたぐ75msハミングについて前後の実PCM RMSを確認し、同じ音程・音量の持続音4個が序盤・中盤・終盤で極端な音量変化を起こさないこと、休符と末尾の無音、サンプル数の厳密一致、外部生成API未使用を検証。
5. 既存Studio、Vocal Bridge、MASTER、プロジェクト保存/復元、13秒WAVなどを回帰検証。

## 残る限界
ここでの「音量安定」は合成テスト音声のRMSであり、実ユーザーのフル尺歌唱を聴感評価した結果ではない。実歌唱素材による比較・マスタリング・iOS/Android実機確認・外部GPU推論・本番公開は別工程。フィルタ内部状態もサンプル単位の完全一致とは保証しない。
