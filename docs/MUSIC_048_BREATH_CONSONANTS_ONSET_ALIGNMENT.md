# MUSIC-048 — 歌い出し同期と息・子音ノイズ耐性

## 目的
MUSIC-047でハミングガイドの高低差と倍音・ビブラートの音程判定を改善したが、子音の無声音、吐息、背景ノイズが混じる歌唱では無意味な音符が生成され得る。また、`extractGuide()` が1024サンプル/12kHz（約85.3ms）の解析窓の先頭時刻をイベント時刻とみなすため、検出したノート開始位置が歌い出しより約20～50ms先行する場合があった。

## 結果
22秒の規則的な合成歌唱近似（16kHz WAV）に、疑似サ行無声音・吐息・低レベル環境ノイズを加えた独立した検査ケースを実ブラウザで実行し、**C4, D4, E4, G4, C5, A4, A5, E5, C5, A3, C4, A4** の**12音が順番通り完全一致**、余計なノートは0だった。
- 元の未補正テストで測定された歌い出し平均絶対誤差は約23.3ms（12音、四捨五入0.01s）。
- `calibrateExtractedGuideOnsets(notes,windowSize,sampleRate)` を追加。新規ガイド抽出ノートのみ、最大30ms（現在の1024/12000窓で25.6ms）をノート開始時刻へ加算し、同じ長さだけdurationから減算。**終了時刻は変えない。**
- 曲先頭付近の音符、長さ0.12秒未満の短い音符、ドラム、不正なノートは変更しない。元入力・元録音・ユーザーの保存済みガイド/MIDIは不変。
- 修正後の実Chromium測定では、開始時刻の平均絶対誤差**13.3ms**。12音/12音、ノイズによる余計なノート0を維持。

## 制限と次の論点
テスト用歌唱は合成音であり、実際の歌唱音声や配信環境のマイク雑音・伴奏漏れ、発話子音の複雑さ、多人声を完全再現したものではない。ノート開始時刻の13.3msはテスト用12音の平均絶対誤差であり、実ユーザー全曲での同期精度を意味しない。人間の鼻歌としての聴感、iPhone/Androidの実機検証、本番公開/共通エンジン接続、GPU生成は依然未完。これらの既存ブロッカーは解除していない。
