# MUSIC-090 — 実録音ピアノを3時間帯で検証・C5重点A/B抽出（2026-11-09）

## ① 現状確認
従来のMUSIC-089音色監査は強弱64〜96の隣接スペクトルを音符開始約0.10秒後の1か所で測る方法だった。音色が立ち上がる瞬間や0.3秒台での干渉を見逃す可能性があった。

## ② 実装
- `integration/piano-timbre-sweep-audit.js` の時間指定を0.40秒まで延長。各音符の有効長の検査は従来どおり。
- `integration/piano-timbre-time-windows.js` で各音符の**開始後0.025秒（attack）、0.130秒（body）、0.320秒（ending）**から2048フレーム（24000Hzで約0.085秒）のHann窓を使い、スペクトル形状差を独立に監査。0.20以上を警戒候補とする。
- `tests/piano-timbre-time-windows.test.mjs` は立ち上がりだけ変化した人工波形、終わりだけ変化した人工波形を明確に識別するテスト。入力PCMは改変しない。
- `tests/real-piano-six-sample-browser.test.mjs` は公式CC0録音ピアノ6ファイルのハッシュを確認してC3/C4/C5の各33ベロシティを3区間で解析し、音量補正前後も比較。
- 特にC5の強弱64→65の中盤を聴感で評価しやすくするため、補正前後の**4秒の2音（64・65）比較WAV**を別途CIで生成し、既存 `tools/piano-listening-qa.html` に読み込めるようにする。
- 30秒曲や各33音の比較WAV、旧エンジン、元の録音を変更せず、追加の検証データとして分離。

## ③ 実録音から確認できた事実
Meta Open Sound Meta PianoのC3/C4/C5×弱強、計6件のOGGプレビューを使用。Chromiumで実際にPCM化。33強弱の隣接差の最大値（スペクトル形状を24周波数帯に正規化した0〜1の指標）：

| 元音域 | 開始0.025秒から | 開始0.130秒から | 開始0.320秒から |
| --- | ---: | ---: | ---: |
| C3 | 0.0452 | 0.0485 | 0.0747 |
| C4 | 0.0177 | 0.0079 | 0.0140 |
| C5 | 0.0032 | **0.1227** | 0.0142 |

- いずれも機械的な警戒値0.20を超える隣接差は0件。
- **C5の開始0.130秒の窓で64→65の差が0.1227**。旧単一窓（約0.10秒時点）での最大値0.0335だけでは気づきにくい音色変化。今後の実耳確認を最優先。
- 音量だけを調整した補正の前後で**正規化スペクトル形状はほぼ変わらなかった**。振幅を補正しただけで録音間の音色の癖は解消されない。
- 出典検証と3窓ブラウザテスト：https://github.com/hitorisamishi222-svg/emuzii-music-studio/actions/runs/42532569574

## 耳での確認方法（実機確認はまだ未合格）
1. 最新実録音CIの「Artifacts」で `asahi-cc0-piano-six-samples-30s` を取得。
2. 中の `C5-64-65-timbre-focus-before.wav` と `C5-64-65-timbre-focus-after.wav` を自分で取り出す（2音目は0.9秒から発音）。この2ファイルが揃っていなければ取得元CIが古い可能性がある。
3. 開発版 `tools/piano-listening-qa.html` でA/Bを順番に選択し、0.13〜0.22秒付近および1.03〜1.12秒付近の音色や音の薄まりを聴き比べる。
4. A/Bの「強弱が自然」「音色が自然」「位相違和感」の評価をJSON保存し、聴感判断を技術評価と別に記録する。
